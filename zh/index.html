一对一视频通话里真正难的部分

Chatter3 是一个免费的英语口语练习 App：两个人，五分钟，一次视频通话。这里是它的工程笔记——六个在真实环境里出现过的缺陷，每一个都写清楚症状、原因、修复，以及保持修复不被改回去的测试。

六篇笔记 · ArkWeb / Cloudflare Workers / WebRTC · 每个修复都有测试 · 数字全部来自线上数据库

六篇笔记

每一个都是被人发现的，不是被单元测试发现的。先写症状，因为症状是最难在事后复现的部分。

ArkWeb · HarmonyOS

卡死的分享页，和文档里那句解释原因的话

按下分享按钮，App 直接卡死。原因是窗口请求交给了一个没有任何组件渲染的控制器——文档明确写着这样会阻塞渲染进程。

ArkWeb · 权限

用户已经授权，App 却仍然说摄像头被拒绝

受保护资源有两层权限：系统那一层，和页面向宿主请求的那一层。宿主从未回答第二次请求，于是每一次都被拒绝了。

Cloudflare Workers · WebSocket

忘记了一个人的 Durable Object

WebSocket 仍然开着，但保存它们的那个字段在对象被回收时消失了。一边把消息全部发了出去，另一边什么也没收到。

Cloudflare Workers · 路由

一条更宽的路由吃掉了 GDPR 导出请求

「导出我的数据」对每一个已登录用户都返回 User not found：因为通用的 /api/user/ 处理函数在文件里排在它前面。

WebRTC · 遥测

对方根本没来，却被告知是你的网络挡住了

失败原因是从 ICE 统计里读出来的。但一个从未发起 offer 的连接不会产生任何候选，于是所有统计看起来都像网络被拦。

WebRTC · 时间

在通话开始之前就开始的计时器

倒计时从匹配那一刻开始，把等待也算成了对话。修它的时候还发现一个符号错误，让两台手机倒数到了不同的秒数。

实测数据

前 133 次通话：连接要多久，对方没来的比例是多少

方法、数字，以及这份数据的边界——附上产生它的查询语句。这是一份来自很早期产品的样本，所以它自己写清楚了这一点。

为什么公开

这些是每个视频通话 App 都会遇到、却没有人写下来的缺陷。公开它们，是因为修复方法对下一个人的用处，大于这个 App 本身；也是因为一篇有真实代码的页面，才有可能被搜索引擎引用。
